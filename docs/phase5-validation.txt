Enhanced KITOS Phase 5 USB/HID validation — 2026-10-27 (Asia/Tokyo)

Scope:
  Phase 4 deferred at user request. Keyboard and mouse selected as first class.
  Existing Phase 0-3 work retained; no reset/checkout/clean used.
  USB common layer, QEMU DWC2, USB 2 control/interrupt IN, hubs, Boot HID,
  console input and EL0 event-read syscall. Broader Phase 5 remains incomplete.

Environment:
  AArch64 GCC 15.2.0; QEMU 10.2.2 raspi4b; Apple clang 21.0.0;
  Python 3.10.6; macOS arm64. QMP uses stdio and UART uses filesystem FIFOs.

Builds — PASS (-Wall -Wextra -Werror, no compiler warnings):
  make TARGET=qemu -j4 all
  make TARGET=hardware -j4 all
  User runtime/probe rebuilt by the USB QEMU target.

Host regression: make test — PASS:
  Existing Block/FAT32/VFS/Timer/SD/SDHCI/page/boot-memory/ELF tests all pass.
  New USB descriptor/Boot HID suite: 363 checks, ASan/UBSan, non-recovering.
    Configuration length, interface/endpoint limits and duplicate addresses,
    truncation and one-bit mutations, keyboard press/release/modifiers/Caps,
    duplicate and held keys, rollover preserving state, mouse signed movement,
    button changes, wheel, invalid report sizes and unsupported protocol.

USB QEMU integration: make test-usb-qemu — PASS (exit 0, about 11 seconds):
  Full-speed hub with keyboard and mouse, descriptor/address/configuration
    requests, class binding and interrupt IN polling through real QEMU models.
  QMP keyboard events produce 'echo usb-ok' at the KITOS monitor and execute it.
  Key press/release events observed, Shift release synthesized on disconnect.
  QMP mouse motion (+7,-5), button down/up reach the kernel input queue.
  Newlib ELF receives motion (+13,-9) and button down through syscall 18:
    [user-input] mouse/uaccess/batch PASS
    Child exits with status 0. Invalid pointer/count and capacity 0 checked.
  Keyboard detach/reattach and successful 'echo reuse' repeated twice.
  Report-protocol tablet remains configured/unbound; existing HID stays bound.
  Nested hub and keyboard enumerate; 'echo nested' executes. Removing the hub
    releases the held modifier and removes the complete descendant subtree.
  Remaining mouse/hub detach; final device count 0, enumeration failures 0.
  Root-attached high-speed keyboard and full-speed mouse independently pass.
  memtest: 8258 checks, reclamation PASS; selftest preemption/control PASS.
  Dedicated disposable SD image; no physical USB passthrough or user SD image.

Full QEMU regression: make test-qemu — PASS (exit 0, about 49 seconds):
  UART/IRQ/tasks, SD/VFS/reboot persistence/read-only FAT checker, no-media boot,
  MMU/EL0 isolation/reclamation, reserved/small-memory DTB and OOM rollback.
  ELF/Newlib/process/FP and the Phase 3 task/FD/argument/heap boundary tests pass
    with the additional USB worker and new syscall present.

Not implemented / not verified:
  Physical Raspberry Pi 4B USB-A: PCIe root complex/VL805 xHCI is not yet
    implemented. Hardware build success is not USB hardware support.
  Low-speed hardware, USB 3/SuperSpeed, high-speed-hub split scheduling,
    endpoint STALL/controller reset recovery are not validated/supported here.
  Generic HID Report Descriptor/Report ID/NKRO/gamepad/tablet, JIS/IME/key repeat,
    LED output, USB storage/network/audio/video/vendor classes remain future work.
  Mouse data is exposed as events; there is no graphical cursor implementation.
  Shared fixed input queues and fixed USB pools; no per-reader event delivery,
    POSIX input device nodes, or general user-facing USB transfer API.

This is the first verified USB/HID milestone, not universal USB support.
