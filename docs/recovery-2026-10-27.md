## 未完成・部分実装

- ユーザー空間環境: Newlibと試験ELFは動作しますが、一般的なPOSIX環境は揃っていません。
  `_fork`, `_execve`, `_link`, `_gettimeofday`, `_times`は`ENOSYS`を返す入口だけです。
- プロセス管理: spawn/waitと限定的な子killは実装済みです。thread、一般のsignal、FD継承・dup/pipe、
  プロセスごとのcwdはありません。monitor/reaperを含む8タスク固定poolです。
- VFS: 固定pool・非待機gateで、同じmountにopen fileがある間はnamespace変更を拒否します。
  POSIXのopen-unlinkや動的なinode寿命管理は残っています。
- メモリ管理: 単一core・単一の低位ARM RAM bank・4 KiB pageで動作します。
  汎用heap/slab、複数bank、大容量メモリ、ASIDによる最適化は未導入です。
- 文書: READMEとPhase 1・2記録には、実装済みのELF/Newlib/FPを将来予定とする記述が残っていました。
  今回READMEとPhase 3の現状説明を更新し、Phase 1・2記録には過去時点の文書であることを追記しました。

## 今回実行した検証

環境: macOS arm64、AArch64 GCC 15.2.0、QEMU 10.2.2、Apple clang 21.0.0、Python 3.10.6。

```sh
make -B PLATFORM=rpi4 TARGET=qemu -j4 all
make -B PLATFORM=rpi4 TARGET=hardware -j4 all
make -B -C usr NEWLIB="$PWD/build/newlib" -j4
make -B test
make test-qemu
```

すべて終了コード0。カーネルは`-Wall -Wextra -Werror`で再コンパイルし、警告なしで成功しました。

QEMU suiteは通常SD起動、同一媒体での再起動、媒体なし起動、予約領域DTB、16 MiB制限DTBで成功しました。
`memtest`は8258 checks。`usertest`終了後のfree/baselineは通常起動で244867/244867、
